This is my work for the CS-340 class


•	How do you write programs that are maintainable, readable, and adaptable? Especially consider your work on the CRUD Python module from Project One, which you used to connect the dashboard widgets to the database in Project Two. What were the advantages of working in this way? How else could you use this CRUD Python module in the future?

I try to write code that is maintainable, readable, and adaptable by separating different parts of the application into reusable components. I also try to use clear variable names, descriptive comments, and well organized functions. The CRUD Python module from project one was a good example of this because all of the MongoDB database operations were contained inside the AnimalShelter class instead of being rewritten throughout the dashboard code. This made it easier to reuse the same database connection and query functions in project two. This also made troubleshooting a lot easier because the database logic and dashboard logic were kept separate. In the future, this same CRUD module could be reused with another Python application, a different dashboard, or another interface that needs access to the same MongoDB database.

•	How do you approach a problem as a computer scientist? Consider how you approached the database or dashboard requirements that Grazioso Salvare requested. How did your approach to this project differ from previous assignments in other courses? What techniques or strategies would you use in the future to create databases to meet other client requests?

I approach problems by breaking them down into smaller components and testing each part as I go. For the Grazioso Salvare project in particular, I first made sure the MongoDB database and CRUD functions worked correctly before connecting them to the dashboard. I then tested the data table, rescue filters, and geolocation map as I added them and then made sure to test them all together at the end. This project was different from previous assignments because it required several technologies to work together instead of focusing on only one program or concept. In future database projects, I would continue to start with determining the client requirements, designing the database structure around those requirements, test queries independently, and then connect the database to the user interface in smaller sections.


•	What do computer scientists do, and why does it matter? How would your work on this type of project help a company, like Grazioso Salvare, to do their work better?

Computer scientists design and develop systems that help the end user solve problems, organize information, automate tasks, and make data easier to use. This matters because a well designed application can save time and help users make better decisions. In the Grazioso Salvare project, the dashboard allows the users to quickly filter a large animal shelter dataset and identify dogs that meet specific rescue training requirements. Instead of manually searching through thousands of records, the user can select a rescue type and immediately see the matching animals, their breeds, and their locations. A system like this could help Grazioso Salvare work more efficiently and focus their time and efforts on evaluating the animals that are most likely to be good candidates for training.
